# Guard Session activation with one-time renewal cancellation

Status: accepted; local implementation complete, deployment pending.

The Session Activation Delivery path, which activates an already-issued CDK, must perform a one-time renewal guard after identity/eligibility checks and the remote CDK preflight have succeeded but before redemption and before `claimActivation`. If the submitted Session reports automatic renewal enabled (`will_renew=true`), the backend issues one deduplicated cancellation request, queries the subscription again, and proceeds only after a definite disabled result (`will_renew=false`) is confirmed. A disabled result proceeds without a cancellation call; a missing, null, or non-boolean renewal state is unknown and blocks activation. The preflight remains the authority for whether the CDK can be redeemed; a healthy or delinquent label does not independently suppress the guard. A timeout, provider error, or ambiguous cancellation response keeps the activation fail-closed in bounded recovery and may require an operator; it must never redeem while renewal status is unresolved. The raw Session remains memory-only through this guard and is not added to the durable activation claim. This decision applies only to Session Activation Delivery; Go Membership Fulfillment keeps its existing final-stage renewal protection and staged-upgrade timing.

The trade-off is an intentional account-setting change before redemption in exchange for preventing a delivered CDK from leaving an unwanted recurring charge enabled. The cancellation is backend-executed rather than a per-order operator click, while operators handle only failed or uncertain recovery. A cancellation response is not evidence by itself: a fresh query must explicitly return `will_renew=false`. Once a disabled result is recorded, retries only recheck it and never issue another cancellation for that order; failed or uncertain calls may make at most three cancellation attempts for the same guard, each preceded by a fresh status query and separated by bounded backoff, with one in-flight request per order and sanitized audit evidence. Exhaustion transfers the guard to human handling instead of calling indefinitely. If redemption later fails or remains uncertain, renewal is never automatically re-enabled; the system only reconciles the redemption outcome and preserves the cancellation evidence. The pre-claim guard uses a durable short-lived reservation bound to the wrapper and preflight-verified account: a same-account retry may resume by querying again after a restart, another account cannot take the wrapper while the outcome is unresolved, and expiry alone never releases an unknown side effect. A resumed attempt must perform fresh preview and preflight and may not reuse old provider tokens or device identifiers. An authenticated administrator may invoke evidence-producing query and bounded recovery actions, but cannot assert a disabled state, bypass the guard, reuse provider credentials, or re-enable renewal through KaWang; critical actions are freshly authenticated and audited. The guard applies to all CDKs that have not yet received a Session activation submission after this decision is deployed, including previously issued but unused wrappers; it does not retroactively mutate activations already in progress or terminal historical outcomes.
