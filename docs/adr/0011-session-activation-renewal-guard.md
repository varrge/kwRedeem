# Guard Session activation with one-time renewal cancellation

Status: accepted; deployed, with active-subscription eligibility strengthened after production evidence on 2026-08-12.

The Session Activation Delivery path, which activates an already-issued CDK, must perform a one-time renewal and subscription-eligibility guard after identity checks and the remote CDK preflight have succeeded but before redemption and before `claimActivation`. The guard queries `POST https://gptserve.freespaces.app/api/subscription/info` with `{ "token": <Session object> }` and maps the authoritative `data.auto_renew` field to `will_renew`; `expire_time` and `expires_at` both equal to `null`, or the provider's explicit no-subscription response, means no active paid subscription. If the submitted Session reports automatic renewal enabled (`will_renew=true`), the backend issues one deduplicated cancellation request through `POST https://gptserve.freespaces.app/api/subscription/cancel` with the same `{ "token": <Session object> }` body, then queries the subscription again. Activation proceeds only after the fresh response definitely confirms both `will_renew=false` and no active paid subscription. The cancellation response is accepted only when `code=200` and `data=1`; any missing, null, or ambiguous renewal or subscription state blocks activation. Remote CDK preflight remains necessary but is no longer sufficient eligibility evidence: production showed that preflight can succeed while final redemption returns HTTP 400 for an account whose paid membership is still active. A timeout, provider error, or ambiguous response keeps activation fail-closed in bounded recovery and may require an operator. The raw Session remains memory-only through this guard and is not added to the durable activation claim. This decision applies only to Session Activation Delivery; Go Membership Fulfillment keeps its existing final-stage renewal protection and staged-upgrade timing.

The trade-off is an intentional account-setting change before redemption in exchange for preventing a delivered CDK from leaving an unwanted recurring charge enabled. The cancellation is backend-executed rather than a per-order operator click, while operators handle only failed or uncertain recovery. A cancellation response is not evidence by itself: a fresh query must explicitly return `will_renew=false`. A paid subscription that is still active enters `account_wait`; this is an expected eligibility wait, does not consume the three fault-recovery attempts, does not claim the wrapper, and permits the same preflight-verified account to submit again after expiry. Every resumed attempt performs fresh preview, preflight, and subscription query and may not reuse old provider tokens or device identifiers. Failed or uncertain calls may make at most three cancellation attempts for the same guard, each preceded by a fresh status query and separated by bounded backoff, with one in-flight request per order and sanitized audit evidence. Exhaustion transfers the guard to human handling instead of calling indefinitely. If redemption later fails or remains uncertain, renewal is never automatically re-enabled; the system only reconciles the redemption outcome and preserves the cancellation evidence. The pre-claim guard uses a durable short-lived reservation bound to the wrapper and preflight-verified account: another account cannot take the wrapper while the outcome is unresolved, and expiry alone never releases an unknown side effect. An authenticated administrator may invoke evidence-producing query and bounded recovery actions, but cannot assert a disabled state, bypass the guard, reuse provider credentials, or re-enable renewal through KaWang; critical actions are freshly authenticated and audited. The guard applies to all CDKs that have not yet received a Session activation submission after this decision is deployed, including previously issued but unused wrappers; it does not retroactively mutate activations already in progress or terminal historical outcomes.
