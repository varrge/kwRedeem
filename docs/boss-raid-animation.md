# Boss 3D 战场与参战小队

当前战场实现使用 Three.js + GLB 模型实时渲染。Boss 与所有参战人物直接放在同一个3D场景内，共用相机、灯光、阴影和深度遮挡。队伍站在右侧地面上，按“横向站满后向纵深增加下一排”组成网格队形。画面没有人物UI卡片、独立人物视窗或格子边框；脚边仅显示脱敏ID和选中/攻击光圈。

## 模型与场景

2026-09-08：以“霜脊古堡 · 黑棘利维坦”为北境中世纪美术样板。画面改为连续山地、风化石墙与拱门、松林、冷雾和暖色火盆；不再使用方形玩具底座、实验培养舱或霓虹界面。灰蓝环境光与旧金色文字用于统一气氛。

8只Boss已全部切换到 `nordic-models` 的独立授权模型：黑鳞巨龙、板甲戟卫、八足蛛后、翼魔、银发巨剑战士、沼泽亡骸、三首猎犬和悬浮魔眼。每只使用不同场景，正式页与离线预览使用相同模型。来源与逐只修改说明见 [首领素材署名](../web/assets/raid-3d/nordic-models/CREDITS.md)。

其中5只保留原生Death倒地动画；蛛后、亡骸和魔眼没有原生Death，采用1.8秒下沉消散并隐藏模型，避免留下不透明影子。蛛后没有骨架、魔眼有骨架但没有动画片段，分别补轻微整体呼吸、悬浮；这两种是程序效果，不冒充原生骨骼动作。亡骸保留原生Idle。没有HitReact的模型使用短暂根节点回震；缺失动画不会退回Idle并阻塞击败完成事件。

参战人物换成 Clement Wu、Nikolaus & Botanic 的同系列成人比例铁甲骑士、兜帽弓手和长袍法师，CC BY3.0，50/58/47骨骼，保留原生Idle/Attack/Hit。颜色收敛为铁灰、皮革绿和暗紫。来源、Blender约束烘焙与修改说明见 [人物署名](../web/assets/raid-3d/nordic-heroes/CREDITS.md)。本轮不用大头KayKit人物，旧资源保留供历史回退。

石墙与铺地贴图来自 Rob Tuytel / Poly Haven，CC0，缩小为512px JPG并本地打包，来源见 [石材说明](../web/assets/raid-3d/nordic-textures/CREDITS.md)。模型、场景均为独立授权素材和项目制作，没有使用《上古卷轴》游戏原始资源。目标是北欧中世纪氛围的网页样板，不代表AAA写实画质。

## 参战者与脱敏

服务端 bootstrap 新增 `participants` 和 `participantCount`。名单来自当前活动的实际报名记录，包含零伤害和未入榜用户，排除管理员配置的账号。按报名时间稳定排序，最多返回60人；当前查看者已报名但在60人之外时，替换最后一个位置让自己可见。超过60人时页面明确显示总人数及本次展示人数。

每条只包含：

- `publicId`：随机报名记录键，供界面稳定匹配。
- `maskedId`：例如 `ID · **A7C2`，由活动和随机报名记录生成。它不保留真实用户ID的前后缀。
- `damage`：当前Boss累计伤害。
- `own`：是否为当前查看者。

这部分数据不包含原始账号ID、用户名、邮箱、头像URL。前端只接受规范的匿名标签，不拿原始身份字段作显示回退，也不向第三方头像服务发送信息。标签是展示代号，不是账户查找凭证，稳定身份匹配使用随机报名键。

桌面与手机统一每页最多6个真实参战模型。`partyFormation()` 按地面X轴先填列，填满再沿Z轴增加下一排：宽屏3列2排，650px及以下2列3排。所有人物脚底对齐地面顶部Y=0.125，格点只用于计算位置，不绘制方框。超过6人可翻页，不足6人只展示真实参战者。自己使用金色脚底光圈。

渲染只调用一次 `renderer.render(scene,camera)`，人物在 `raid-party-world` 组内，使用正常蒙皮网格，投射并接收同场景阴影。OrbitControls旋转/缩放时，Boss、人物、地形共同运动，远近关系和遮挡由深度缓冲决定。窗口尺寸变化只重新分配世界坐标，不重建人物骨骼。脚边 `**A7C2` 是跟随角色的无背景文字Sprite，辅助技术通过隐藏文本名单读取完整的 `ID · **A7C2`；不泄露原始账号。

三种人物按随机报名标识稳定分配，不使用账户资料。每个可见人物通过SkeletonUtils克隆独立骨骼和AnimationMixer，几何体与材质共享模板；只有本次贡献者播放原生攻击动作。模板只加载一次，翻页回收实例骨骼、ID贴图和脚底光圈，关闭页面同时释放缓存；失败时保留该位置的匿名标识，不用简陋人物替代，也不把待发攻击归给别人。

## 动作与状态

- 参战人物平时保持固定站姿，不循环播放Idle动画。Idle只用于取第一帧姿态，避免游侠抬弩动画每1.6秒复位。只有本人新增伤害时播放一次约0.7秒攻击，完成后回到相同站姿；动作切换在mixer更新完成后执行，避免结束帧覆盖站姿。此规则不改变Boss本身和环境的动画。
- 按 `publicId` 比较同一Boss上次与本次的个人累计活动伤害。谁的伤害增加，谁的模型挥剑、射弩或施法，释放光束并高亮脚底光圈及标识；其他玩家保持待机。光束起点直接取本人右手挂点的世界坐标，不从UI坐标反投影。多人同时贡献则只有这些人分别攻击，场内提示其脱敏ID和本次伤害增量。活动伤害已由服务端按实际扣费及倍率计算，前端不再推算账单。
- 若本次贡献者在另一页，在当前页攻击播放完毕后切到其所在页，再由本人模型攻击；一次同步的跨页动画依次播放，每页约0.9秒。手动翻页、切换Boss、隐藏场景、减少动态或活动结束会丢弃尚未播放的攻击，避免回放旧消费；手动暂停只冻结当前效果。
- 首次见到的参战者没有上次伤害基线时只更新数据。相同数据、伤害回调和首次进入均不生成攻击。脱敏标签不作为匹配键，即使两人标签相同也不会把攻击归给另一人。
- 场景加入环境粒子，颜色跟随主题，冰原为下落雪粒；确认击败时播放扩散光环和一次碎光爆发。不增加真实伤害或发放奖励。
- 特效使用固定上限：6束光、3圈冲击波、96个火花和72个环境粒子；不会随请求数量无限创建。切换Boss、隐藏页面、减少动态和中止时清理短暂特效。暂停保持当前画面。
- 首次加载、切换Boss、重复同步及后台恢复不补播历史伤害。
- Boss血量低于25%时加快其待机；零血/结算中保持存活，直到服务端确认击败。参战人物依旧静止，除非本人有新的攻击。
- 确认击败后，有原生Death的模型播放一次并保持末姿；其余三只下沉消散。两种路径均只发出一次完成事件，重复快照不重播。进入下一Boss等待完成事件，最长8秒避免加载失败卡住。死亡使用实际经过时间推进，10FPS下也不会被粒子动画的单帧步长限制拖慢；暂停/隐藏会重置时间基线，恢复时不跳过暂停的动作。减少动态直接显示最终状态。
- 活动中止/未击败到期保持静止，不伪造死亡或奖励。
- 页面隐藏、场景离屏或手动暂停时停止渲染循环；减少动态模式保留静态姿态。
- 使用OrbitControls实现360°水平环绕和上下俯仰。鼠标左键/手机单指拖动旋转，滚轮/双指缩放，鼠标右键/双指移动平移；俯仰、距离和平移范围受限，避免穿到地底或丢失战场。“复位视角”恢复该屏幕尺寸下的默认镜头。手动调整在暂停/减少动态时仍可用。
- 触控手势仅由画布接管；操作数据框和画布之外仍可滚动网页。镜头变化不触发伤害。

PVE充值倍率奖励、预算、月末恢复1.0及旧MVP兼容逻辑保持原实现。

## 文件、构建和预览

- `web/raid-arena-source.js`：小队和3D播放器源代码。
- `web/raid-nordic-environment.js`：连续地形、古堡遗迹、松林及本地石材加载。
- `web/raid-nordic.css`：预览与正式页共用的北境界面风格。
- `web/raid-arena-effects.js`：固定容量的环境粒子、光束、冲击波与胜利特效。
- `web/raid-arena.css`：对阵HUD、辅助技术名单和内嵌响应式布局。人物队形在Three.js世界坐标中计算。
- `scripts/build-raid-3d.mjs`：生成正式与离线预览bundle。
- `web/raid-arena.js`：正式页面使用，约600KB，模型按当前Boss单独加载。
- `web/raid-arena-preview.js`：离线预览使用，嵌入8个Boss和3个人物GLB。
- `web/assets/raid-3d/nordic-models/`：8只新Boss，合计约7.47MB；最大单只板甲戟卫约3.67MB，正式页按需加载。
- `web/assets/raid-3d/nordic-heroes/`：成人比例骑士、弓手、法师GLB，合计约1.03MB。
- `web/assets/raid-3d/nordic-textures/`：石墙/铺地512px JPG，合计约110KB。
- `web/assets/raid-3d/models/`：8只旧Boss仅作历史资源保留，新版3D播放器不再加载；原heroes目录也不用于新版3D人物。
- `web/boss-raid-animation-preview.html`：直接浏览器打开即可。6个小队成员与伤害均为模拟数据，不访问账号API。选择“本次消费玩家”，点击按钮模拟该玩家消耗10额度，按预览1.2倍伤害产生12点伤害，仅此人攻击；重置创建新模拟战斗并清空未完成攻击。

修改源代码或模型后运行 `npm run build:raid-3d`，不要手工编辑生成文件。客户端无需从CDN加载库、模型或纹理；正式入口不会下载离线预览模型合集。

WebGL初始化失败时，正式页面使用原来的 `raid-boss.js` / `raid-boss.css` 二维图集，并显示脱敏参战者列表。3D模型加载失败时提供重试；WebGL上下文丢失时显示刷新提示。原二维素材的作者与授权继续保留在各自CREDITS中。

整套3D战场部署需发布此前的小队API改动、正式页面、bundle、raid-nordic.css，以及nordic-models、nordic-heroes、nordic-textures目录和各自署名文件；先发布资源再切换页面。旧二维回退资源继续保留。本次剩余7只Boss替换仅涉及前端和素材，无需数据库迁移。离线预览bundle仅用于预览并已嵌入新模型和贴图。Three.js的MIT声明见 [第三方说明](../web/assets/raid-3d/THIRD_PARTY.md)。

```sh
npm run build:raid-3d
node --test tests/sub2api-raid*.test.js
node scripts/check-raid-hero-motion.mjs
node scripts/check-raid-3d.mjs
npm run check
```

浏览器检查覆盖8个场景、5只原生死亡与3只消散、暂停、匿名标签、0/60人、分页、自己在末页、320–1440宽度地面列数与逐排填充，以及鼠标/触控旋转、缩放和视角复位。测试直接检查人物与Boss属于同一个Scene、人物启用阴影、脚边文字挂在人物根组、没有CSS人物格子或独立相机。独立动作回归使用可控时钟核对6人无消费时骨骼不动、3种职业仅本人攻击、攻击后精确回到固定站姿、暂停恢复和减少动态；同时检查8只Boss实际姿态的接地/悬浮高度、死亡完成一次、消散隐藏、恢复显示和减少动态直接完成。攻击检查还包含多人同批、跨页贡献者、重复同步、负向校正、首次快照和真实手部起点。特效检查包括容量上限、存活时间、禁用和切场清理。未进行真实充值或生产活动配置修改。
