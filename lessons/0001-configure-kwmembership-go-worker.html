Lesson 01 · Production setup

配置 kwMembership Go 自动化

目标不是“学会 Go 语法”，而是让你能独立确认 Worker 指向正确数据库、配置后台凭据、观察订单状态，并始终把真实付款留在受控发布流程里。

约 20 分钟当前服务器版默认不扣款
kwRedeem 后台保存凭据与展示状态
SQLite / WAL唯一共享数据源
Go Worker完整自动化流程
Xvfb Chrome私有虚拟屏幕中的结账引擎

关键理解：Go 不需要第二套数据库，也不需要扩展。它直接读写 kwRedeem 的数据库；“不用打开浏览器”指不需要人工打开或操作窗口。服务器 Chrome 运行在私有 Xvfb 虚拟屏幕中，并始终由 Go 控制。

Step 1

确认服务器上的三个位置

内容当前服务器路径
Go Worker/opt/kwmembership
Go 运行参数/etc/kwmembership.env
kwRedeem/var/local/1panel/apps/openresty/openresty/www/sites/key/index

登录服务器：

ssh root@64.90.1.22
Step 2

配置 Go 的运行参数

编辑文件：

sudoedit /etc/kwmembership.env

当前服务器应使用：

KAWANG_PROJECT_ROOT=/var/local/1panel/apps/openresty/openresty/www/sites/key/index
KWMEMBERSHIP_CHROME_PATH=/usr/bin/google-chrome-stable
KWMEMBERSHIP_CHROME_PROXY_SERVER=http://127.0.0.1:7890
KWMEMBERSHIP_VISIBLE_BROWSER=true
KWMEMBERSHIP_BROWSER_TIMEOUT_MS=90000
  • KAWANG_PROJECT_ROOT：告诉 Go 去哪里读取 kwRedeem 的 .env、数据库路径和 JWT 密钥。
  • KWMEMBERSHIP_CHROME_PATH：Go 控制的 Chrome 可执行文件。
  • KWMEMBERSHIP_CHROME_PROXY_SERVER：只让结账 Chrome 走服务器本机的新加坡代理。
  • KWMEMBERSHIP_VISIBLE_BROWSER：服务器设为 true 后使用 Xvfb；正常流程仍然全自动。
  • KWMEMBERSHIP_BROWSER_TIMEOUT_MS：一次结账浏览器会话的总超时，默认 90 秒。
这个文件不需要复制 DATABASE_PATH 或 JWT_SECRET。Go 会从 kwRedeem 的 .env 读取，确保两边使用同一数据库和同一加密密钥。
Step 3

运行不会领取订单的自检

sudo bash -lc '
  set -a
  source /etc/kwmembership.env
  set +a
  cd /opt/kwmembership
  ./bin/kwmembership-worker --check
'

成功标志：shared kwRedeem database configuration is valid

它会检查共享数据库表结构，并在配置的 Xvfb 模式下实际启动一次 about:blank Chrome；不会获取订单、调用 Provider 或付款。

Step 4

在 kwRedeem 后台保存业务凭据

打开项目后台，进入 ChatGPT 会员自动化 → SpaceX Card OpenAPI，填写：

字段用途要求
app_idSpaceX Card OpenAPI 身份接口未提供时可留空
app_secret读取卡片和交易、执行受控资金动作首次配置必填
Webhook 签名密钥验证卡交易回调签名配置 Webhook 后填写
SpaceXCard GPT Token旧版兼容字段，Go Session Cookie 流程不读取无需填写

点击 保存加密凭据。保存后页面只显示“已配置”，不会回显明文。

保存这些凭据会把付款 Gate 重置为 disabled。这是正确的安全默认，不要在基础配置阶段改成 canary 或 automatic。

SpaceX Card 交易 Webhook 地址配置为：

https://apikey.vsakura.top/api/webhooks/spacexcard/card-transactions
Step 5

初始化卡片库存

仍在同一后台页面，找到 卡片库存初始化与刷新：

  1. 首次配置点击 初始化全部卡片。
  2. 等待任务完成，不要在进行中更换 OpenAPI 凭据。
  3. 以后日常同步使用 刷新库存与行情。

成功标志：实施状态中的“库存初始化”显示已完成，卡片列表只展示脱敏资料。

Step 6

启动并确认 Go Worker

sudo systemctl enable --now kwmembership-worker
sudo systemctl status kwmembership-worker --no-pager
sudo journalctl -u kwmembership-worker -n 100 --no-pager

后台 实施状态 应看到：

字段正确值
运行主体go
状态运行中
版本当前 Go 发布版本
最近心跳 / Tick持续更新
最近错误无
结账执行器go-session-api-checkout-v2
浏览器扩展不需要
Step 7

用新订单验证自动接收

  1. 客户正常创建会员订单并提交可用 Session。
  2. Go 按 WORKER_POLL_MS 执行 Tick（默认约 5 秒），自动发现部署水位线之后创建的新会员订单。
  3. 在后台“会员履约记录”刷新查看状态与错误码。
历史订单不会自动批量接收。如果确实需要处理旧订单，只能在“会员履约记录”输入订单号并使用“补建单笔履约”。补建只建立编排记录，不等于授权付款。

Session 失效时，该订单会显示 SESSION_INVALID，不会因为一个坏 Session 停掉所有新订单。

Step 8

知道在哪里停止：基础配置完成

Gate 模式含义本教程是否执行
disabled不允许进入真实付款边界是，保持此状态
no_charge只做无扣款页面验证后续受控验证
canary只批准明确选中的单笔履约，且各阶段仍需页面快照批准单独上线流程
automatic只对已精确启用、已达资格的范围自动执行Canary 成功后再评估
不要把“Go 服务正在运行”理解成“必须开启付款”。Worker 在 Gate 关闭时仍会做安全检查、状态推进和必要对账；真实付款需要新的 go-session-api-checkout-v2 Canary 与范围授权。

附：本地开发环境怎么启动 
cd /Users/varrge/workspace/kwRedeem
npm install
npm run db:init

cd /Users/varrge/workspace/kwMembership
cp .env.example .env
# .env 中保持 KAWANG_PROJECT_ROOT=../kwRedeem
bash scripts/build.sh
bash scripts/check.sh
bash scripts/start-worker.sh

Go 官方说明，go build 会编译包及其依赖并生成可执行文件；本项目的 scripts/build.sh 已经封装了这一步。
