因为库存是 0，第一笔测试订单会真实调用一次 SpaceX 发码并扣发码服务费。创建这笔订单就是本次 Canary 的资金动作，不要同时提交第二笔。
Step 1

在独角数卡创建专用测试商品

  1. 新建一个只用于 Canary 的商品，例如“SpaceX Plus 自动化测试”。
  2. 履约方式选择人工交付，让 KaWang 接管交付内容。
  3. 不要复用正在售卖的 Plus 商品，避免普通客户进入测试。
  4. 记下商品的 product_id；没有单独 SKU 时使用 sku_id=0。
Step 2

在 KaWang 后台添加唯一映射

进入 商城自动发货 → 商品映射，填写：

字段填写值
商品 ID上一步的真实 product_id
SKU ID真实 SKU；没有则填 0
履约类型SpaceX CDK 自动激活
SpaceX 套餐Plus
KaWang 站点建议选当前启用的 plus91
前缀系统自动锁定为 91GPTPLUS
状态启用
映射只影响映射保存后发现的新订单。现有 26 个 blocked 任务不会自动重试，也不会因新增映射突然发码。
Step 3

确认 Webhook 地址

在 SpaceX 对应 API Key 的 Webhook 配置中订阅 gpt_direct.* 和 cdk.*，地址使用：

https://apikey.vsakura.top/api/webhooks/spacex-cdk

Webhook 是主同步路径；即使偶发漏推，Worker 仍会用结果接口补账。

Step 4

提交唯一一笔 Plus 订单

  1. 购买刚才的测试商品，数量必须为 1。
  2. 完成支付，让订单进入待人工履约/履约中状态。
  3. 等待最多 30 秒，然后刷新 KaWang 的商城履约任务。
  4. 在本单明确完成或失败以前，不要创建第二笔测试订单。

正常路径是：pending → 发码/分配 → succeeded。商城收到的内容只能包含一个 91GPTPLUS-... 包装码和提交网址，绝不能出现 SXC-... 上游码。

若状态是 issuance_uncertain 或“发码结果待核对”，立即停止，不要点击重试；系统故意禁止自动补买。
Step 5

核对发码与资金契约

在后台 SpaceX CDK 资产 中应看到一条 Plus 记录：

字段通过标准
本地状态allocated / 已分配
上游状态unused
包装 CDK与商城交付的 91GPTPLUS-... 一致
资金上限必须存在金额和币种
完整 SpaceX CDK默认不展示，也不需要查看
若显示 contract_blocked / “接口契约不完整”，系统已经安全保存唯一完整码，但不会交付。不要重试或重新购买；若同时显示“无限授权（已拦截）”，按无限授权处理课选择后续路径。
Step 6

用包装码完成玩家激活

  1. 打开商城交付内容中的 KaWang 提交网址。
  2. 输入 91GPTPLUS-... 包装码并验证。
  3. 提交目标 ChatGPT 账号的 Session JSON；原始 Session 只在本次请求内使用。
  4. 等待状态从“正在提交/排队中/开通中”进入“会员开通成功”。

若进入 review 或 pending，页面会显示“等待支付对账”，此时不要重复提交，Webhook 或 Worker 会继续同步。

状态动作
