Core rules

一场协作战，不是一张换皮消费榜

共享奖励承接团队动机，Boss 级独立排行承接竞争动机；每一笔伤害都来自权威真实用量。

01主动加入

每月加入一次，只统计加入后的真实使用。

02正常调用

API 使用产生 actual_cost，不额外烧余额。

03伤害转换

首期实际消耗按 1.0x 同时进入血量和个人贡献。

04Boss 结算

最终同步后冻结排名、人数与奖励。

05连续推进

下一只贡献归零，最终 Boss 通关即结束。

伤害只认权威发生时间

远端用量 ID 去重，按 created_at 分配。单条用量不可拆，溢出伤害不进入下一只 Boss。

基础伤害 = remote actual_cost
首期最终伤害 = 基础伤害 × 1.0x

参战边界

  • 账号须在活动开始前注册
  • 允许中途加入，不追溯历史消费
  • 所有 API Key 按稳定用户 ID 合并
  • 内部与测试账号明确排除

结算边界

  • 每只 Boss 独立贡献与奖励
  • 月末 10 分钟仅补同步月末前用量
  • 未击败 Boss 不发物质奖励
  • 结算快照冻结后不改写排名

首月数值草案

正式发布前使用最近三个月真实用量回放，活动开始后不可临时加血或减血。

Reward economy

名额随有效参与人数增长，成本在发布前封顶

每只 Boss 独立配置实际消耗入榜门槛。低于门槛的伤害仍削减血量，但不计入奖励人数。

浮动 MVP 名额

MVP 名额 = min(3, floor(有效参战人数 / 10))

00–9 名有效参战者
110–19 名有效参战者
220–29 名有效参战者
330 名及以上，上限固定

奖品边界

共享奖励小而确定，MVP 奖励高价值但受预算与审核约束。

奖品适用阶段交付规则
额度共享一期远端 admin balance 幂等发放；首期 MVP 不使用
活动抽奖卡MVP一期必须绑定结算后仍有效的摇摇乐活动
订阅套餐MVP二期延长同分组有效期，不损失剩余天数
限时倍率MVP二期绝对倍率 + 时长 + 优惠用量上限

发布校验

月度最坏成本 = Σ（共享奖单价 × ceil(Boss 血量 / 本 Boss 入榜门槛) + 可解锁 MVP 奖励）
预算内超出预算时禁止发布

自动发放

  • Boss Clear Reward 默认自动
  • 小额额度与抽奖卡默认自动
  • 失败保持原奖品并幂等重试

审核后发放

  • 大额额度、订阅与倍率默认审核
  • 作弊取消资格后顺延下一名
  • 保留原始排名与最终获奖审计

Operations

配置一旦开战即锁定，后台只处理事实与履约

一期按单个 Sub2api 连接运行。业务逻辑落在 KaWang API 服务，通过已保存的远端管理员密钥读用量和发奖励。

活动状态

提前中止不伪造击杀：已结算奖励继续履约，当前 Boss 不发正常奖励。

运营后台必须看见

  • 远端同步游标、最后成功时间与错误
  • Boss 血量构成及单条权威用量
  • 原始排行、获奖名单与顺延记录
  • 奖励审核、重试和倍率权益状态
  • 全部高风险操作审计日志

上线分期

先验证真实消耗增量和参与结构，再承担订阅与倍率的复杂履约。

上线前模拟

回放最近三个月用量，校准 2,000 / 4,000 / 7,000 / 11,000 血量、门槛和最坏预算。

一期

真实用量伤害、连续 Boss、全程 1.0x、浮动名额、共享额度、MVP 抽奖卡、后台审计与当前互动页面。

二期

订阅安全延期、限时倍率权益、用量封顶、排队生效、备用奖励和冲突告警。

暂不进入

跨连接聚合、SSE/WebSocket、任意素材上传与无限关卡，等一期数据证明必要性后评估。
