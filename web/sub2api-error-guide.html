报错处理指南

把常见 API 报错拆成「现象、原因、处理动作」三步，适合直接嵌入 Sub2api 用户后台或公告页。

快速定位 先看状态码
500 422 429 504 502 400 499 401
错误码 缓存 测评 模型名

HTTP 状态码

500 服务端内部错误通常是上游繁忙或请求超时 ⌄
报错示例
status_code=500, error sending request [provider_id: ]
原因
节点压力过高、上游响应慢，或临时链路异常。
处理
等待片刻后重试；若连续出现，降低并发并切换到其他可用模型。
422 请求体无法解析JSON 为空、损坏或字段类型不对 ⌄
报错示例
status_code=422, Failed to deserialize request body
原因
客户端发出的 body 不是合法 JSON，或缺少接口要求的必要字段。
处理
重新检查请求体，尤其是逗号、引号、数组对象结构和 Content-Type。
400 参数不在允许范围字段存在，但取值违反限制 ⌄
报错示例
status_code=400, budget_tokens: Input should be greater than or equal to 1024
原因
请求参数低于下限、高于上限，或与当前模型能力不匹配。
处理
按错误提示调整对应字段；不要只重试，先改参数。
499 客户端提前断开服务端还没返回，调用方先结束连接 ⌄
报错示例
status_code=499, bad response status code 499
原因
本地超时时间太短、用户取消请求，或代理层主动断开。
处理
重新发起请求；长输出任务建议调大客户端 timeout。
504 网关等待超时代理层等待上游响应超出阈值 ⌄
报错示例
status_code=504, bad response status code 504
原因
上游响应时间过长，或当前网络链路抖动。
处理
稍后重试；减少单次上下文长度通常能降低触发概率。
429 触发速率限制请求频率或并发量超过限制 ⌄
报错示例
status_code=429, This request would exceed your account's rate limit.
原因
短时间内请求过密，或多个客户端共用同一额度。
处理
降低并发、加入退避重试；批量任务不要无间隔重放。
401 鉴权失败API Key 无效、停用或填错位置 ⌄
报错示例
status_code=401, Invalid or inactive API key
原因
Key 复制不完整、前缀错误、已被禁用，或客户端 Header 配置不正确。
处理
重新复制后台 Key，确认使用 Authorization Bearer 方式，并检查账号状态。
502 上游网关错误请求已到达代理，但上游没有正常完成 ⌄
报错示例
status_code=502, Upstream request failed
原因
上游节点繁忙、短暂不可用，或链路返回异常响应。
处理
稍后重试；如果只在某模型出现，先切换模型或线路。

缓存策略说明

对没有显式设置 cache breakpoint 的请求，服务端可自动补齐缓存策略。这样能兼容部分不支持缓存断点的客户端，减少重复上下文带来的成本浪费。

测评站注意事项

模型输出存在波动，单次测评不一定能代表真实稳定性。遇到思维签名长度、格式化输出等检测项异常时，优先核对测评参数是否互相冲突。

建议固定思考强度、避免在格式化输出测试里同时强制工具调用，并多测几次取综合结果。

模型名称差异

如果偶尔看到非常规模型名，可能是官方灰度或 A/B 测试路由。只要请求质量和计费正常，不必把模型名差异当作故障。

claude-quoll-v7-hr-ab-low-p

先做这四步

  • 确认状态码：4xx 多为请求或鉴权问题，5xx 多为临时链路问题。
  • 复制完整报错：保留 request id、model、时间点，便于定位。
  • 先改参数再重试：400、422、401 不会靠盲目重试恢复。
  • 控制并发：429、499、504 常和超时或并发策略有关。
