Track 1 · API Calling

5 分钟完成第一次 API 调用

先用 OpenAI 兼容的 /v1/chat/completions 验证通路，再选择 CLI、桌面客户端或 AI 编程 GUI。

1. 在 Sub2api 创建自己的 API Key

  1. 登录 Sub2api，打开 API Key / 密钥管理页面。
  2. 创建一个只给自己使用的 Key；完整密钥通常只在创建完成时展示一次。
  3. 把 Key 只复制到你即将使用的客户端，不要粘贴进教程页面、截图或工单。
教程不会自动填 Key

教程是公开网页，不能接触你的真实凭据。怀疑泄露时，回到 Sub2api 控制台撤销并重新生成。

2. 用一条 curl 请求验证通路

把三个占位符换成你的值。模型名以你的 Key 可访问的模型为准。

curl /chat/completions \
  -H "Authorization: Bearer <YOUR_API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<MODEL_ID>",
    "messages": [
      {"role": "user", "content": "请用一句话介绍你自己。"}
    ],
    "temperature": 0.2
  }'

复制按钮只复制代码文本，不会收集你粘贴进去的 Key。

API Base URL

。如果你从不同域名打开教程，以 Sub2api 管理员提供的 API 源站地址为准。

3. 成功与常见报错

成功响应通常包含 choices 数组和模型生成的文本。先确认 HTTP 状态码为 2xx，再检查响应是否包含可读内容。

现象先检查什么
401 / 鉴权失败Authorization 是否为 Bearer <Key>，Key 是否被撤销或带多余空格。
模型不可用先调用 /v1/models，确认模型 ID 和 Key 的可用范围。
余额不足 / 额度不足登录 Sub2api 查看余额或套餐，不要靠重复重试解决。
请求超时先减少上下文和输出长度，再检查客户端代理、网络和服务状态。

4. 先查模型，再复制到客户端

curl /models \
  -H "Authorization: Bearer <YOUR_API_KEY>"

从返回结果中复制完整模型 ID，填入下一步客户端的 Model 字段。不要在教程里写死会变化的模型列表。

5. 客户端配方

所有客户端先遵循同一组信息：API Key、Base URL、模型 ID。不同工具的字段名和 URL 拼接规则可能不同。

客户端类型接入方式状态配置提示
GUI 能打开不等于 API 已接通

只有 runtime 真实完成一次请求，才算客户端配方验证通过。排错时先确认到底是哪一层保存了配置。

6. Claude Code、Codex CLI、Gemini CLI

  • 把 Sub2api Key 只写入本机 CLI 配置或环境变量。
  • Base URL 必须按该 CLI 的协议要求填写，可能不是同一个路径。
  • 先用一个低成本模型和最短请求验证，再开始长任务或代码修改。
  • Codeg/CCGUI 托管 CLI 时，不要为了“看起来完整”再复制一份 Key 到 GUI。
Track 2 · Subscription Purchase

看懂套餐，再安全购买

教程公开说明套餐字段；真实余额扣款、订单记录和账号数据只在 Sub2api 登录后的页面处理。

1. 购买前先看三件事

字段你要确认什么为什么重要
价格本次会扣除多少余额购买前确认余额足够，避免扣款失败。
有效期套餐从购买成功起生效多少天决定什么时候需要再次购买。
额度 / 限额每日限额或模型访问范围避免把有效期误认为无限使用。
价格和套餐以 Sub2api 当前页面为准

教程不写死价格、有效期和模型列表；这些内容可能由管理员调整。

2. 登录 Sub2api

点击“购买订阅”会进入 Sub2api 的登录页；登录成功后回到购买页面。已登录用户会直接进入，不需要重复认证。

3. 确认余额扣款

  1. 选择当前可购买的套餐，核对价格、有效期和额度。
  2. 点击余额购买后，确认弹窗中的金额和套餐名称。
  3. 等待页面返回购买结果，不要连续点击多个套餐。
  4. 在购买记录或我的套餐页面确认结果。
不要把重复点击当成重试

金额已经扣除但订单没有结果时，先保留订单号和页面状态，停止继续点击。

4. 购买后确认

  • 购买记录出现对应订单，状态为成功或明确显示等待处理。
  • 我的套餐页面中的生效时间和额度符合购买前说明。
  • API 使用仍然使用自己的 API Key；购买不会自动把 Key 填进客户端。
